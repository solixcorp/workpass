# OIDC app logout

The admin app-session list combines unexpired, unrevoked access and refresh tokens. A revoke marks both kinds revoked, clears refresh rotation replay material, and preserves consent unless explicitly requested otherwise. Self-disconnect also removes consent. The list of connected apps includes consent-only clients, so that a person can withdraw a previous grant even after its tokens expire.

Administrators can configure `backchannelLogoutUri` and `backchannelLogoutSessionRequired` (also accepted and returned using their OIDC snake-case names). Client metadata is stored in the provider's `oauthClient` columns and appears in the application integration GET. The endpoint must use HTTPS and cannot be an IP literal or local hostname. The existing `oidc_logout_uri_approvals` table is an independent, operator-managed allowlist: a URL must be explicitly approved there before an administrator can select it. Validation alone cannot prevent DNS rebinding or a public name resolving to a private address; operators must enforce suitable DNS and network egress restrictions as well. No redirects are followed.

Logout tokens use the provider's JWT plugin and its ES256 JWKS key, with issuer, client audience, subject, issued/expiry times, unique ID, and the OIDC back-channel event. For a session-required client a separate token is sent per known session ID; when session IDs have already been lost, delivery is reported as failed rather than falsely claiming session-scoped logout. Delivery is best effort with a five-second request timeout and per-app outcomes; revocation is committed before network calls. An RP's successful HTTP response is not proof that its local session ended. No retry queue is provided.

The all-sessions better-auth endpoints and the better-auth admin ban endpoint capture affected apps before mutating sessions or triggering the database ban revocation, then invoke app logout only after success. A one-session admin revoke and revoke-other-sessions do not invoke universal logout. The provider may independently emit its own session-deletion notifications, so duplicate delivery is possible. Existing database triggers still revoke tokens on ban, including bans performed outside these HTTP hooks; those other paths do not currently send a back-channel notification.

This does not implement SAML single logout, WS-Federation logout, or SWA logout. JWT access tokens already verified locally by resource servers may remain usable until expiry unless those servers check revocation. A failed database revocation returns 503 on the new APIs; best-effort hooks log errors after the primary action has already succeeded.
